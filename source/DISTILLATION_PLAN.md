# 《STL源码剖析》蒸馏与交付方案

## 目的与参照流程

用户要求模仿“编码理论”项目中“Boolean-vector-research-skill生成”的全套过程，基于指定PDF使用仓颉蒸馏，并把规范内容上传 `WEveboy/STL_Houjie-skill`。参照项目先形成章节精读与研究导向方案，再把可执行部分整理成单一入口、原子能力卡和配套工具，保存来源、边界、测试及发布记录；本项目沿用这种组织，不照搬其数学能力、测试数字或旧版本结论。

本次使用书籍方法蒸馏的 `cangjie-skill`，而非根据一本技术书推测侯捷的人格、失败经历与个人信念。主体能力是读懂源码、推演状态、检查前置条件及验证结果。人类读者由章节精读与DIGEST承接，Agent通过同一组能力卡及资源完成具体任务。

## 来源与阅读范围

- 来源身份：侯捷《STL源码剖析》，用户提供的简体中文扫描版，共542个PDF物理页。正文研究早期SGI STL与GNU/Cygnus C++ 2.91.57。
- 定位约定：所有证据用章节与PDF物理页并列定位；插入广告后不能用固定偏移转换成印刷页。
- 文本获取：扫描页OCR只作本地可检索底稿，保留来源指纹和抽取记录；短引文、代码符号、数值与图解的重要结论回查页图。原生文字附页和书内正文分开处理。
- 读过的范围与证明过的范围分别报告。目录与章节扫描覆盖整书，不意味着所有代码行、宏组合、异常分支和图中节点都经过独立证明。
- 出版元信息按实际材料保留置信边界；文件创建/修改日期不能替代出版年。末页元信息与版权页证据应区分。
- 公开仓库不收原书PDF、整章OCR、页图、个人本地路径、依赖副本或认证信息；只收原创解释、必要短引文及定位、可维护源文件和最终文档。

## 从八章精读到五类候选

阶段0产出整书骨架和独立关键任务清单，再以五个视角分别提取。框架视角寻找分工、状态转换和排障流程；原则视角寻找前提、不变量、公式与复杂度口径；案例视角定位原书演示并区分历史输出与本次实验；反例视角保留错误方向、错误单位及缺条件的失败机制；术语视角统一书中概念的用法和近邻区别。

独立视角有助于发现遗漏，但多位提取者引用同一页不等于多份独立来源。候选数量也不是质量指标。先用目录和正文建立任务，再问每项任务有何证据、交付到哪里；不能由已选能力倒推一个恰好全部通过的覆盖表。

章节精读保留“定义—条件—机制推导—小例—易错点”，不以案例替代一般条件。DIGEST沿元素操作把配置器、traits、容器、算法和配接器连起来，同时保留有序树与哈希这两条独立路线。书目、旧站点与旧工具链移植留为历史背景，不编译成现代部署建议。

## 能力边界：一个入口，18项可独立读取的能力

发现入口采用 `stl-houjie`，并在内部按任务路由。这样用户不必安装18个互相竞争的入口，而每张卡仍有独立输入、步骤、输出、前提及测试。需要拆分为独立Skill时，应依据真实使用和触发冲突证据重新规划，不仅因某项内容有专名就增加入口。

| 能力slug | 任务及交付重点 |
|---|---|
| source-reading | 源码入口、组件依赖、规格与实现差异 |
| object-lifetime | 储存/对象账本、构造销毁配对与失败清理 |
| pool-allocation | SGI正数小请求分档、链表与内存池状态 |
| iterator-dispatch | 关联型别、最低能力、标签分派与操作次数 |
| vector-state | 三边界、扩容、就地插入与对象范围 |
| linked-sequences | list/slist链接、节点身份与区间转移 |
| deque-navigation | 区容量单位、逻辑位置到区与偏移映射 |
| heap-adapters | 堆范围、容器长度与受限访问接口 |
| ordered-associative | 树序、颜色/黑高、键提取与唯一性 |
| hash-table | 散列定位、相等、碰撞链与重散列 |
| copy-contract | 目标对象、范围长度、复制方向及重叠条件 |
| logical-end | remove/unique的有效前缀、新尾与物理删除 |
| ordered-ranges | 有序集合、二分边界与比较关系 |
| sorting-selection | 全排序、部分排序、秩选择与归并保证 |
| numeric-functors | 初值、折叠顺序、参数方向与操作策略 |
| iterator-adapters | 插入、反向、流迭代器的接口变化 |
| callable-adapters | 绑定、否定、组合及返回值去向 |
| range-reordering | reverse、rotate与排列后继的结果合同 |

各卡R段只保留必要短引文与章节/物理页定位；I用原创语言解释；A1区分原书演示和合成演练；A2限定触发与相邻任务；E给输入、分支、输出和完成标准；B说明错误用法、实现限制及不支持范围。能力之间的阅读依赖通过稳定ID建立，不依赖卡片的偶然排序。

## 三重验证、取舍与勘误

V1检查来源是否足以支持限定范围内的做法，V2检查合法新输入能否按该做法得到可核结果，V3检查固化后是否减少遗漏、统一口径或稳定交付。通过、参考、待核查、去重淘汰四类分别记录；有意义的参考内容进入overview或glossary，而不是悄悄消失。

下列问题要显式保留：deque示例把第三模板参数、字节数和元素数混用；nth_element文字容易把操作前的40误读为操作后阈值；for_each某处被概称为不能改元素，但PDF330明确承认可调用对象能修改元素；copy的历史memmove路径不能使错误重叠方向成为通用前提。处理方式是保留原文问题的定位、解释冲突、对清楚的源码机制单独核验，不冒称作者承认勘误。

原书无法支持的部分不扩成active能力：完整红黑删除修复、任意自定义类型的字节复制许可、简化配置器的多线程安全、所有现代库的布局或增长参数、任意比较器都合法等。现代标准与实现材料若被使用，必须单列补充来源，不能并入侯捷原书结论。

## 工具与实际任务验收

可重复的有限状态推演适合确定性工具，例如分档索引、deque区位、堆序、逻辑范围和带重数集合运算。工具只是透明教学模型，不冒充完整STL实现。输入限定类型、单位和预算，拒绝非法范围；输出记录所采用的实现模型和前提。涉及真实C++对象语义、迭代器类别或算法行为的部分，还要通过独立可运行小程序核验，不能以Python模型本身证明C++实现正确。

每个active能力至少准备一个正常任务和一个边界/缺输入任务。先固定检查项，再给执行者任务；保存实际回答与产物，主流程按结果判定。触发/路由、实际输出、来源核查、语义评估分开记录；没有输出的计划样本仍算未完成，不从分母删除。无Skill基线对照未完成时，不宣称新Skill提高正确率或节约时间。

测试不只核对某份历史数组。排序检查有序性和多重集保持，选择检查秩及两侧关系，节点转移检查身份与链接，生存期检查成功构造范围与清理配对。实现允许多种合法中间状态时，不把单一状态写成唯一断言。结构校验通过仅表示格式、引用和资源符合要求，不表示方法已独立证明。

## 编译、双平台包与发布

能力卡与元数据构成Capability Bundle，作为唯一可编译事实源；通过仓颉编译得到single产物，再运行技能包格式/相对引用/frontmatter检查。生成目录不手改；需要修正时改源卡或资源，重新编译。维护源与安装成品一并保存，来源和发布审计可互相追踪。

Codex安装包交付同一个完整技能目录及安全安装器；DeepSeek版本沿用参照项目的Harness插件形式，而不是把普通网页对话说成有本地工具执行能力。两平台必须保持能力卡和计算资源一致，核对清单与SHA256；首次安装防意外覆盖，升级先备份。用户本次明确要求仓库发布，是否安装到全局目录不作为上传前置条件。

教程按“准备运行环境—安装仓颉—安装本Skill—首次调用—命令行复现—验证结果—排错—升级”组织，分别说明宿主差异；需要PDF时保留TeX源、编译记录及页面检查。不可用的命令和未验证下载入口不得写成已经成功。

发布前再读远端main状态，只提交筛选后的内容，保留他人变更；已有分支更新使用预期SHA约束，不强制覆盖。主分支保存维护所需源文件、测试、能力卡、用户文档及CI，版本安装包和校验文件进入Release。首次空仓库在交付准备好后初始化。GitHub工作流先解析并检查条件表达式，尤其带冒号的字符串，避免重演参照项目早期YAML错误。

上传后核对提交SHA、文件清单、关键页面与CI；若创建Release，再核对标签、资产链接、下载哈希及解包安装烟测。只有实际上传的资产才称已发布，只有实际完成的验证才写通过。最终日志保存失败、修复、未完项与当前版本，使后续维护能从准确状态继续。

## 读者交付与验收边界

公开发行目录中，`source/`保存本方案、章节精读、DIGEST和审计材料，`skills/stl-houjie/`保存可安装产物。三份读者文稿里的能力链接按该发行布局编写；在蒸馏工作目录里尚未存在的目标不表示已经上传。

完成标准不是“生成很多Markdown”。读者应能解释同一次元素操作中的储存、对象、遍历与算法条件；Agent应能据输入选择正确能力，补齐必要信息并交付可核结果；维护者应能从来源定位、能力ID、测试与提交记录追踪结论。任何重要来源或输出评测缺口，都必须保留在交付说明及流水线状态中，不以完整模板掩盖。
